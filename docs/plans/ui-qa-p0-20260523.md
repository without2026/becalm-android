# UI/UX P0 QA Plan, 2026-05-23

## Product Frame

BeCalm is a relationship-memory assistant, not a mail, calendar, recording, or file viewer. The P0 bar is therefore trust: a user must understand whether a source is connected, whether new evidence is being organized, and whether a person, schedule, commitment, or identity judgment is confirmed or still needs review.

## P0 Criteria

- Wrong person, schedule, commitment, account ownership, or self identity can appear confirmed.
- A user action such as OAuth, share, import, speaker selection, or identity save has no clear success, failure, retry, or pending state.
- Internal implementation objects such as filenames, provider lanes, source rows, or pipeline status become the primary user object.
- The app accepts or persists a sensitive decision without an explicit approval moment.

## Slice 1: OAuth Completion Return

- Problem: Railway returns a browser completion page with `becalm://oauth-complete`, but Android does not route that deep link to a user-visible completion state.
- Current code: backend `app/api/oauth_completion_page.py`; Android `AppDeepLinks`, `BecalmNavHost`, `SourcesListScreen`.
- Goal: Browser success/error returns to Settings > Data Sources, refreshes source state, and shows a clear success/error snackbar.
- Non-goal: Change OAuth token exchange or provider sync semantics.
- Data/schema: none.
- Failure/retry/idempotency: repeated deep link opens may show the snackbar again but must not duplicate connection rows.
- Tests: `AppDeepLinksSpecTest`; broad Android compile through targeted unit test.
- Rollout/rollback: Android-only APK update; backend page already emits the deep link.

## Slice 2: Google Multi-Account Source UX

- Problem: backend/Room can hold multiple `source_connections`, but OAuth UI collapses status to provider-level `Connected`.
- Current code: Android `EmailOAuthConnector`, `CalendarOAuthConnector`, `OnboardingViewModel`, `SettingsIdentityScreen`; backend `source_connections`, mail/calendar OAuth status.
- Goal: Gmail and Google Calendar surfaces show existing account rows by capability, expose "add another account", and keep disconnect/delete ownership controls account-scoped.
- Non-goal: Merge Gmail and Calendar into one row; they remain separate capability rows even for the same Google identity.
- Data/schema: use existing `source_connections` rows; no new table expected unless current contract proves insufficient.
- Failure/retry/idempotency: same account reconnect updates the same row; different account creates a distinct row; failed status refresh does not hide existing rows.
- Tests: connector unit tests, onboarding/settings ViewModel tests, source connection repository tests.
- Rollout/rollback: Android copy/UI plus backend status contract verification.

## Slice 3: Share And Image Import State

- Problem: sharing an image into BeCalm returns to Schedule without a durable "added, organizing, review needed, failed" surface.
- Current code: `ShareImportActivity`, `SourceImportRepository`, `EvidenceImportUi`, Today/Schedule state.
- Goal: share/import creates a visible evidence status item in-app and keeps background processing non-blocking.
- Non-goal: Full screenshot OCR result design or image preview gallery.
- Data/schema: likely reuse local raw ingestion sync status; add projection only if needed.
- Failure/retry/idempotency: duplicate shares dedupe by existing raw event contract; failed upload exposes retry.
- Tests: share import unit tests, source import repository tests, targeted UI state tests.
- Rollout/rollback: Android-only; backend image extraction path unchanged unless status fields are missing.

## Slice 4: Human Titles For Imported Evidence

- Problem: screenshot and meeting primary titles are raw filenames.
- Current code: `SourceImportRepository`, `MeetingImportRepository`, raw event detail/timeline projectors.
- Goal: primary titles read as human evidence objects, e.g. "메신저 캡처, 5월 23일 14:30" or "회의 녹음, 5월 23일 14:30"; original filename moves to metadata/detail.
- Non-goal: Perfect transcript-derived meeting summary in this slice.
- Data/schema: no migration if title is locally generated; metadata storage may use existing `source_ref`/artifact metadata.
- Failure/retry/idempotency: fallback title must be deterministic and stable across retries.
- Tests: repository title tests, raw event rendering tests.
- Rollout/rollback: Android-only, backend extraction can later replace generic titles with richer summaries.

## Slice 5: Speaker Review Explicit Confirmation

- Problem: selecting a speaker immediately confirms the choice even though the sheet also shows a confirm action.
- Current code: `EvidenceImportViewModel`, `EvidenceImportUi`, `MeetingImportRepository`.
- Goal: tap selects only; explicit confirm persists mapping and queues extraction. Include a "later/cancel" path that does not imply failure.
- Non-goal: Redesign the full diarization review model.
- Data/schema: none.
- Failure/retry/idempotency: cancel leaves preview pending/reviewable; confirm is single-flight.
- Tests: ViewModel test for selection not confirming; UI test where confirm button is required.
- Rollout/rollback: Android-only.

## Slice 6: Self Identity Mirror Success

- Problem: adding a self identity anchor updates local UI before remote mirror succeeds and hides remote failure in logs.
- Current code: `SettingsIdentityViewModel`, `IdentityRepository`, `SettingsIdentityScreen`.
- Goal: success state appears only after backend mirror succeeds; remote failure leaves a retryable error and does not silently clear the input.
- Non-goal: Redesign all self-identity onboarding.
- Data/schema: no schema change; use existing anchor and source ownership contracts.
- Failure/retry/idempotency: local optimistic row must not appear as confirmed if backend create fails; retry should be safe.
- Tests: Settings identity ViewModel success/failure tests, repository tests if needed.
- Rollout/rollback: Android behavior change only; backend contract unchanged unless tests reveal mismatch.

## Completion Gate

- Each slice must pass its closest targeted tests before moving on.
- After all slices, run `./gradlew testDebugUnitTest`, `./gradlew lintDebug`, and `./gradlew assembleDebug`.
- For backend-touching slices, run targeted `pytest` plus `python3 -m compileall -q app`.
- If a Samsung device is available, install the debug APK and smoke OAuth return, share import, speaker review, and Settings > My Info.
